# 认知接力强化（RELAY 机制引入）

## 0. 问题诊断

### 现状

- 流水线的 11 个 Prompt 模板以 Java/Maven 微服务为假设编写，包含精确到路径、注解名、章节号的扫描指令——在 Java 项目上质量极高
- 非 Java 项目依赖 NON_JAVA 模式（SKILL.md 185-197 行的「请自行语义映射」说明），实际可用但质量不够稳定
- 原 `implementation_plan.md` 提出的 `[!RELAY]` 方案声称已完成，但仓库中无任何 RELAY 代码落地

### 核心判断

1. **Java 模板不动**：它们是经过实战验证的高精度指令集，具体指令比抽象意图更利于 AI 发挥
2. **NON_JAVA 模式不动**：当前 Java 模板 + NON_JAVA 说明已经能跑出非 Java 项目的结果，不需要额外写 unknown 适配指令
3. **不引入 PROJECT_TYPE 变量**：保持现有 Java / NON_JAVA 二分。真正了解项目技术栈细节的是 step-01 的执行 Agent，不是指挥官的 `ls` 命令
4. **不泛化 § 硬编码**：先验知识注入中的 `§5 子模块职责定义` 等引用在 Java 项目上精度高、经过实践验证；非 Java 项目上 AI 已经在自动处理指向虚空的引用——泛化它在 Java 上是降级，在非 Java 上收益很小
5. **[!RELAY] 是唯一真正需要加的东西**：它补充的是模板和指挥官都无法预见的项目特异性发现，尤其在非 Java 项目上，step-01 的 RELAY 是后续步骤获取具体扫描方向的关键情报源

---

## 1. 核心目标

1. 引入 [!RELAY] 步间动态指令通道，让上一步的项目特异性发现能以「显式指令」形式传递给下一步
2. 在非 Java 项目上，利用 step-01 的 RELAY 向后续步骤传递技术栈清单和扫描路径建议
3. Java 项目完全零降级

---

## 2. 详细设计

### 2.1 [!RELAY] 格式定义（所有模板统一）

在每个模板的输出要求节（`[!SUCCESS]` 闭环块之后）追加：

```markdown
> [!RELAY] 定向审计约束
> - **物理事实 (Context)**: [本步发现的、对下一步有决定性影响的关键事实]
> - **推演约束 (Constraint)**: [基于事实，强制下一步重点分析的具体内容]
> - **物理锚点 (Anchors)**: [对应的文件路径或行号]
```

step-final-assembly 和 step-audit-rules 是终点步骤，不需要追加（无下一步可接力）。

### 2.2 指挥官 RELAY 处理（SKILL.md 三处改动）

**变量初始化（§一 变量初始化段）**：

在现有变量列表末尾新增：

```
RELAY_STRATEGY   = "无先验接力偏好，请按标准考古规范执行。"
```

**Step 1 渲染（§三 Step 1）**：

在现有变量替换列表中新增一条：

```
- `{{RELAY_STRATEGY}}` → `${RELAY_STRATEGY}`（由上一步提取得出，首步为默认值）
```

注入位置：在 Prompt 的「最高指令挂载」之后、「先验知识注入」之前，插入以下内容：

```markdown
# 0. 核心接力策略（最高执行优先级）

{RELAY_STRATEGY 的值}

**[执行准则]**: 以上为上一步指挥官转交的"强制任务"。你必须优先响应并回显证据，否则将被判定为考古失败。
```

**Step 6 提取（§三 Step 6）**：

在现有 `[!SUCCESS]` grep 之后，增加 `[!RELAY]` 提取：

```bash
grep -A 10 '\[!RELAY\]' ${LOG_DIR}/{step_name}.log | head -12
```

- 找到 → 更新 `RELAY_STRATEGY`
- 未找到 → 重置为默认值「无先验接力偏好，请按标准考古规范执行。」，在 pipeline.log 记录一条 WARN（不熔断）

**降级策略**：RELAY 缺失不等于流水线失败（与 `[!SUCCESS]` 的硬熔断不同）。RELAY 是补充通道，不是主通道。但缺失必须留痕，方便事后审计。

### 2.3 step-01 的 NON_JAVA 特殊处理（SKILL.md NON_JAVA 处理段）

在现有 NON_JAVA 说明的末尾追加一段，仅对 step-01 生效：

```
此外，作为全链路第一个接触项目源码的步骤，你的 [!RELAY] 必须额外包含：
- 本项目的实际技术栈清单（框架、包管理器、构建工具、测试框架）
- 项目的物理目录结构与各目录职责推断
- 对后续步骤（契约提取、数据模型、异步机制等）的具体扫描路径建议
这些信息将被指挥官用于后续步骤的接力注入。
```

这使 step-01 的 RELAY 成为非 Java 项目后续步骤的核心情报源。

### 2.4 step-01 硬编码 bug 修复

当前 step-01-skeleton.md 第 13 行：

```
请静默读取 {{output_dir}}Legacy_SignInCenter_Claims.md
```

`SignInCenter` 是某个具体项目的名字，应改为：

```
请静默读取 {{output_dir}}Legacy_{{project_name}}_Claims.md
```
